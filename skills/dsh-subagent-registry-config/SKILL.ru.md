# Руководство по dsh-subagent-registry (пользовательские суб-агенты / use_agent)

> Плагин dsh: регистрирует `~/.dsh/agents/*.md` как вызываемые пользовательские
> суб-агенты — `use_agent` запускает по имени, `ask_agent` задаёт вопрос фоновому
> запуску и ждёт ответа, прерванный запуск автоматически продолжается при
> повторном вызове. Каждый суб-агент — это полноценная сессия dsh (полная сессия,
> персистентность, возможность продолжения), работающая через встроенный provider
> `spawn`; плагин не меняет сам dsh.

## Поддержка двух версий хоста

Один и тот же пакет проверен на реально выпущенных SDK DSH `0.2.0-rc.2` и `0.2.1-rc.2` (линия RC/стабильных; линия alpha не поддерживается). Способ запуска выбирается автоматически по публичным API (обнаружение возможностей): на старой версии — `start` для переднего плана, `startContinuable` для фона; на новой — `startActivation` с доставкой `caller` для переднего плана и `parent` для фона, при этом persona и ограничения инструментов для листовых агентов устанавливаются на собственную область суб-агента на границе `subagent/start`. При сбое выбранного интерфейса сразу выдаётся ошибка — повторный запуск через другой интерфейс не выполняется. Продолжение и уточняющие вопросы читают формат сессий каждого хоста отдельно; миграция между версиями не предоставляется. Хост должен монтировать персистентность сессий и сервис `sessionQuery`; англоязычная инструкция по делегированию ролей одинакова на обеих линиях.

## Формат определения агента (`<agentsDir>/<name>.md`)

Один markdown-файл — это один агент: в `---` frontmatter записываются метаданные,
а тело **дословно** используется как persona (system prompt) этого суб-агента.
Все ключи frontmatter:

| Ключ            | Обязателен | По умолчанию          | Описание и поведение при ошибке                                                                                                  |
| --------------- | ---------- | --------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `name`          | да         | —                     | id агента = имя файла (без .md). Отсутствует или пуст → **весь файл отбрасывается**.                                              |
| `deep`          | нет        | `1`                   | Неотрицательное целое. `0` = лист (может работать, но запрещено запускать суб-агентов); `≥1` = относительный бюджет глубины. Не целое/отрицательное → файл отбрасывается. |
| `display_name`  | нет        | отсутствует           | Необязательная метка UI; суб-агент помечается как `display_name ?? name`, продолжение и уточняющие вопросы находят старый запуск по ней. |
| `description`   | нет        | отсутствует           | Однострочное описание, выводится в реестре в описании инструмента `use_agent`, чтобы основная модель могла выбрать агента.         |
| `model`         | нет        | отсутствует = наследование | Маршрут `provider/model`; значение без слэша считается именем provider + наследование модели по умолчанию в этом развёртывании. |
| `thinking`      | нет        | отсутствует = наследование | `off`/`low`/`medium`/`high`/`max`, **с учётом регистра**; другое значение → файл отбрасывается.                                   |
| `background`    | нет        | отсутствует = передний план | Строго `true`/`false` (с учётом регистра, без сокращений); другое значение → файл отбрасывается. `true` = запуск в фоне по умолчанию, можно уточнять через ask_agent. |
| `maxRounds`     | нет        | отсутствует = глобальный | Положительное целое, лимит числа раундов для агента (переопределяет глобальное `dsh-tui.maxRounds`); не положительное целое → файл отбрасывается. Потребляется жёстким стоп-механизмом TUI. |

Минимальный шаблон:

```markdown
---
name: my-agent
display_name: Мой агент
description: "Однострочное описание, показанное в реестре use_agent"
model: opencode-go/deepseek-v4-flash
thinking: high
deep: 0
---

You are my-agent. Этот markdown-текст будет использован дословно как system prompt.
```

Внимание: **неизвестные ключи молча игнорируются** — `extensions` / `tools` / `color`
не работают (соглашение `extensions` из fun-agent здесь не поддерживается), их наличие
только введёт в заблуждение тех, кто будет читать файл позже.

## Интерактивный мастер настройки (ask_user_question)

Когда пользователь говорит «помоги создать суб-агента XX / добавь агента» — не
сваливайте документацию на него, используйте `ask_user_question` для сбора ответов
по одному вопросу, а затем **напишите файл сами**:

1. **Имя + обязанности**: имя в kebab-case (= имя файла), одно предложение для
   `description` (попадёт в реестр use_agent; укажите, когда его запускать).
2. **Модель**: наследовать модель развёртывания по умолчанию (рекомендуется, оставить
   пустым)／указать маршрут `provider/model`.
3. **Уровень thinking**: не задавать (наследование)／off / low / medium / high / max.
4. **Глубина запуска**: `deep: 0` (лист, запрещено запускать суб-агентов)／`deep: 1`
   (по умолчанию, можно запускать дальше).
5. **Передний план или фон**: передний план, разово (по умолчанию)／`background: true`
   (фоновая непрерывная сессия, основной диалог не блокируется, можно уточнять через
   `ask_agent`).

После сбора сгенерируйте `<agentsDir>/<имя>.md` и запишите в каталог agents (тело —
persona system prompt по описанию пользователя, **используйте дословно**, не переписывайте
своими словами), затем сообщите, когда изменения вступают в силу:

- **Новый файл можно вызывать по имени сразу** — `use_agent` при выполнении
  перечитывает файл с диска. Откройте «Суб-агенты» в левой навигации Web или
  обновите вручную — реестр инструментов синхронизируется в следующих запросах
  модели, перезапуск не требуется; сохранение/удаление на странице тоже
  обновляет автоматически. В чисто CLI/TUI без Web-страницы управления реестр
  обновляется при следующем монтировании плагина.
- **Изменения существующих файлов** (тело, frontmatter) вступают в силу при
  следующем вызове `use_agent`, без перезапуска.

## Конфигурация самого плагина (семь ключей entry config)

У плагина нет пространства имён settings — конфигурация вешается на **блок patch,
который его монтирует** (секция `config:` элемента `insert` в cordis.patch.yml
бандла, то есть entry config):

```yaml
- insert:
    - id: dsh-subagent-registry
      name: '@aiwayds/dsh-subagent-registry'
      config:
        agentsDir: ~/.dsh/agents   # каталог файлов агентов; только этот литерал по умолчанию разрешается через $DSH_HOME, пользовательские пути используются как есть (с раскрытием ~)
        provider: spawn            # через какой subagent provider запускаются агенты (переиспользует spawn из dsh-base)
        toolName: use_agent        # имя инструмента запуска
        askToolName: ask_agent     # имя инструмента уточняющих вопросов
        # leafDenyTools: []        # список запрещённых инструментов для листовых агентов deep:0; пусто = статический умолчание (встроенные инструменты запуска dsh + toolName) ∩ зарегистрированные инструменты хоста; непустое передаётся как есть (без пересечения)
        resume: auto               # auto | opt-in | off
        language: zh               # zh | en | ru (по умолчанию zh), см. раздел «Переключение языка плагина» ниже
```

| Ключ             | По умолчанию   | Описание                                                                                                                              |
| ---------------- | -------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `agentsDir`      | `~/.dsh/agents` | Только литерал по умолчанию разрешается через `$DSH_HOME` (то есть `$DSH_HOME/agents`); пользовательское значение после раскрытия `~` используется **как есть**, без перепривязки к dsh home. |
| `provider`       | `spawn`        | Provider суб-агентов.                                                                                                                  |
| `toolName`       | `use_agent`    | Имя инструмента запуска; при изменении список запретов для листовых агентов подстраивается автоматически.                              |
| `askToolName`    | `ask_agent`    | Имя инструмента уточняющих вопросов.                                                                                                   |
| `leafDenyTools`  | `[]`           | Пусто = статический умолчание (`subagent`/`subagent_fork`/`workflow`/`ralph` + `toolName`) ∩ инструменты, зарегистрированные на хосте сейчас (защита от устаревших имён, вызывающих fail-fast хоста); непустое передаётся **как есть**, без пересечения, устаревшие записи отклоняет валидация хоста. |
| `resume`         | `auto`         | Режим продолжения, см. следующий раздел.                                                                                               |
| `language`       | `zh`           | Язык интерфейса/гида/предустановленных шаблонов агентов: `zh` / `en` / `ru`; после изменения перезапустите dsh, см. следующий раздел. |

### Лимиты параллелизма и глубины (с dsh 0.1.7 — официально управляются)

Число одновременно активных суб-агентов и глубина вложенности управляются
**официальным сервисом dsh-subagent** (плагин не ведёт собственный счётчик
параллельности/очередь): `maxActiveSubagents` (по умолчанию `8`) и `maxDepth`
(по умолчанию `1`) — оба volatile-поля, настраиваются на лету без перезапуска.
Когда пользователь хочет «запустить несколько параллельных суб-агентов / разрешить
более глубокую вложенность», пишите в patch профиля
`subagent: { maxActiveSubagents: N, maxDepth: M }` или вызывайте в рантайме
`settings.update('subagent', …)`; `deep` в файле агента лишь ужесточает этот
официальный бюджет (`deep: 0` — лист, инструменты запуска убираются).
`maxRounds` (лимит раундов на агента) остаётся ключом frontmatter этого плагина:
у официального механизма нет бюджета раундов, его продолжает потреблять жёсткий
стоп-механизм TUI хоста.

## Переключение языка плагина (language)

Плагин поставляется с тремя языками: `zh` (китайский, по умолчанию), `en` (English) и `ru` (Русский); выбор задаётся ключом `language` entry config.

- Как изменить: установите `language` в `zh` / `en` / `ru` в конфигурации плагина (cordis.patch.yml или настройки плагина в web), затем перезапустите dsh, чтобы изменения вступили в силу.
- Область действия: тексты веб-панели управления, этот гид (соответствующее тело и описание маршрутизации для модели) и предустановленные агенты, засеиваемые при первой установке (`templates/agents/<language>/`).
- Существующие файлы агентов никогда не перезаписываются: чтобы сменить язык уже созданных агентов, отредактируйте `~/.dsh/agents/*.md` напрямую или очистите каталог agents и дайте засеиванию пересоздать его на новом языке.
- Когда пользователь спрашивает, как переключить интерфейс на английский/русский: объясните шаги выше или измените конфигурацию за него и напомните о перезапуске. Триггеры: язык, язык интерфейса, сменить язык, language.

## Продолжение и уточняющие вопросы

- **Три режима `resume`**: `auto` (по умолчанию) = если у этого агента в текущем
  диалоге есть прерванный запуск, он автоматически продолжается; `opt-in` =
  продолжение только при явном `resume: true` в вызове; `off` = никогда не
  продолжать автоматически (явный `resume: true` у вызывающего всё равно
  принудительно продолжает). `fresh: true` наоборот принудительно начинает заново.
  На уровне параметров инструмента `resume` и `fresh`, а также `background` и
  `resume` взаимоисключающие.
- **Определение прерывания**: по **последней записи accounting `turn/end`** в
  журнале событий персистентности суб-агента — не `completed` (error / aborted /
  max-tokens / сбой без записи) — значит, запуск прерван и его можно продолжить.
  Продолжение использует ту же persona/модель/набор инструментов и продвигает только
  один continuation-раунд; при неудаче можно продолжать многократно, прогресс
  накапливается. Продолжение зависит от персистентности сессий; если чтение,
  занятие или восстановление выбранного старого запуска завершилось ошибкой,
  выводится ошибка и второй экземпляр задачи не создаётся — повторный запуск только
  при явном `fresh: true`.
  Новые activation-запуски на переднем плане используют короткий префикс-тег
  `[fg] <display_name ?? name>` (в v0.14.0 был длинный префикс
  `[use_agent foreground] `, распознавание совместимо); старые передне-плановые
  запуски по-прежнему помечаются обычным тегом one-shot. Фон сохраняет обычный тег,
  оба передне-плановых можно продолжать.
  Позже отменённый pending input или незакрытый новый раунд тоже считаются
  продолжаемыми — нельзя смотреть только на ранний `completed`.
  Публичные API обеих поддерживаемых версий пока не поддерживают managed cold
  resume с текущей композицией и доставкой caller-only; продолжение на переднем
  плане ведётся через `agents.resume`, его можно остановить отменой вызова, но оно
  не занимает слоты параллельности manager'а и не управляется `interrupt_agent`,
  а продолженный суб-агент не может связаться с родителем через штатный
  `send_message`. Новые запуски и фоновые уточняющие вопросы управляются manager'ом.
- **`ask_agent` для background-запусков**: задаёт вопрос последнему фоновому
  запуску и **ждёт ответа** (по имени `agent` или возвращённому при запуске
  `agent_id` — передаётся ровно одно из двух; опциональный лимит `timeout` в
  секундах, `≤0` считается переданным). Разовый передне-плановый запуск уточнить
  нельзя — его продолжение идёт через механизм resume в `use_agent`.

## Диагностика подключения и использования (debug)

Локализуйте проблему в три шага: «установлен ли → смонтирован ли → работает ли»,
затем проверьте следы использования. Подставьте вместо `<profile>` фактическое имя
профиля (`tui` / `web` / `desktop` / `headless`…); у каждого профиля плагины и
монтирования независимы.

### Шаг 1: установлен ли (есть ли пакет в профиле)

```sh
dsh plugin --profile <profile> list    # по сути передаёт аргументы pnpm из каталога профиля; должен показать @aiwayds/dsh-subagent-registry
ls ~/.dsh/profiles/<profile>/node_modules/@aiwayds/   # эквивалентная проверка
```

### Шаг 2: смонтирован ли (попал ли insert-блок в слой композиции)

```sh
dsh dump-config --profile <profile>    # должен показать элемент insert с id: dsh-subagent-registry и его config
grep dsh-subagent-registry ~/.dsh/profiles/<profile>/cordis.patch.yml
```

Внимание: dump-config показывает **результат композиции** слоя patch, без
материализованных в рантайме значений схемы.

### Шаг 3: работает ли (сканирование каталога + регистрация инструмента + видимость модели)

- `ls ~/.dsh/agents/`: при первом запуске (каталог был пуст) внедряются три
  предустановленных агента workhorse / oldfox / rubber-duck — если они на месте,
  сканирование agentsDir работает.
- Прямо в сессии спросите модель: «перечисли доступные тебе инструменты» — должны
  появиться `use_agent` / `ask_agent`, а в описании `use_agent` — реестр агентов.
- Заодно проверьте маршрутизацию skill: поговорите с моделью «настрой мне
  суб-агента» — должен подтянуться скилл `dsh-subagent-registry-config`.

### Использовался ли (следы использования)

- **Карточки/просмотр**: `/history` в tui-pi для просмотра сессий, либо панель
  активности на карточках раундов web/«Флайт» — строка `🔧 use_agent · ✔` это один
  запуск.
- **Прямая проверка на диске (универсально для любого профиля)**: каждая сессия —
  это `~/.dsh/sessions/<каталог рабочей области>/<id сессии>/session.v3.jsonl.zstd`,
  посчитайте вызовы напрямую:

  ```sh
  zstdcat ~/.dsh/sessions/<каталог рабочей области>/<id сессии>/session.v3.jsonl.zstd | grep -c use_agent
  ```

  Больше 0 — сессия вызывала; сам суб-агент тоже отдельная сессия dsh в том же
  корне sessions.

### Симптомы → точки разбора

| Симптом | Где искать | Куда чинить |
| --- | --- | --- |
| В `dsh plugin … list` нет плагина | Установка | `dsh plugin --profile <profile> add @aiwayds/dsh-subagent-registry`, перезапустить dsh |
| В dump-config нет insert-блока | Монтирование | Проверить cordis.patch.yml профиля, пересмонтировать и перезапустить |
| Инструмент есть, реестр пуст | agentsDir / расположение файлов / frontmatter | См. «Устранение неполадок» 1, 2 ниже |
| Инструмент и реестр есть, модель не вызывает | Выбор модели | Написать в `description` агента «когда меня запускать»; в TUI можно дополнительно использовать registeredOnly из tui-pi |
| При вызове ошибка `ctx.subagents.start is not a function` | Загружен старый плагин или хост вне проверенного диапазона | Проверено для DSH `0.2.0-rc.2` и `0.2.1-rc.2` (линия RC/стабильных; alpha не поддерживается); уточнить фактическую версию плагина, обновить и перезапустить; не предполагать совместимость с другими версиями хоста |

## Устранение неполадок

1. **Файл агента отброшен** → смотрите ошибки парсинга в логах запуска/loader:
   отсутствует `name`, `deep` не целое или отрицательное, недопустимое значение
   `thinking`/`background` — во всех случаях **весь файл отбрасывается** (не
   пониженный ремонт).
2. **Агент не появился в инструменте `use_agent`** → проверяйте по порядку:
   правильно ли настроен agentsDir (по умолчанию `$DSH_HOME/agents`); лежит ли файл
   `<имя>.md` прямо в верхнем уровне каталога (подкаталоги не рекурсивны);
   корректен ли frontmatter и совпадает ли name с именем файла (см. предыдущий
   пункт). Открытие или обновление Web-страницы управления синхронизирует реестр;
   в чистом CLI/TUI реестр обновляется при следующем монтировании, при этом новые
   файлы можно вызывать по имени сразу.
3. **Предустановленные агенты пропали/изменены** → при первом запуске три агента
   workhorse / oldfox / rubber-duck внедряются только если каталог пуст; существующие
   файлы никогда не перезаписываются, удалил — значит удалил. Удаление плагина тоже
   не трогает файлы в `~/.dsh/agents/`.

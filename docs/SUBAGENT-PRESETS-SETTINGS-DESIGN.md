# Subagent 预设设置界面设计

状态：用户已确认整合设计及 Q11 承载方式，按“设置入口 → 主工作区完整管理页 → 独立表单页”执行。使用 Comet 核实公开接口、管理实现与独立验收；本文不代替 Comet 的阶段检查。

## 目标与范围

在 DSH 设置中直接查看、创建、复制、编辑和删除 dsh-subagent-registry 实际读取的角色预设，减少手工编辑文件。入口名称为 **Subagent 预设**。

继续使用当前插件配置解析出的 `agentsDir`，以原有 Markdown 文件作为唯一数据源，不另建一套预设数据库。默认目录按 `DSH_HOME/agents` 解析；当前机器为 `C:\Users\caiqy\.dsh\agents`。不同 profile 使用同一目录时共享数据。

保留现有两条宿主支持线：DSH `0.2.0-rc.2` 和 `0.2.1-alpha.2`。通过插件公开扩展接口实现，不修改客户端宿主源码。

## 页面与操作流程

### 列表页

- 从设置左侧的 **Subagent 预设** 入口打开主工作区的独立完整管理页，与宿主的会话组合预设页面区分；不将完整管理界面塞入设置内容区。
- 显示实际预设目录和共享范围提示；加载真实目录顶层的 `.md` 普通文件。
- 正常行显示内部名称、显示名（如有）、职责描述、模型或“继承默认”、状态，以及编辑、复制、删除操作。
- 错误行显示文件名、无法加载的具体原因、修复和删除操作。文件名与内部名称不一致等导致不可调用的情况也必须显示诊断，不能显示为可正常调用。
- 提供“新增”和“刷新”；使用现有顺序规则，不额外增加分类、标签或复杂筛选。
- 区分加载中、目录无预设、读取失败。读取失败不得伪装成空列表，也不得自动补写默认预设。

### 创建、复制和编辑页

点击操作后，主工作区的预设管理页切换为独立表单页，具有明确标题、“返回列表”、保存和取消操作；不是列表中的展开区域或行内编辑器。管理页自身会丢弃输入的动作先确认；切换宿主其他页面或打开设置时不弹确认，草稿保留在当前客户端，回来继续。

基本字段：

- 内部名称：创建/复制时必填且唯一；编辑时只读。新建名称须能安全用作文件名，不允许路径片段或覆盖已有预设。新文件名与内部名称保持一致。
- 显示名、职责描述。
- 模型：允许继承默认；从宿主模型目录提供可用选项，保留已有的自定义/当前不可用路由，不能因列表暂时无法加载就清空已存值。保留现有路由语义。
- 思考强度：继承或现有解析器支持的 `off/low/medium/high/max`。
- 系统提示词：普通多行文本编辑区，保留 Markdown 内容，不增加编辑器依赖。

高级字段：派发深度、后台运行、轮数上限。缺省语义沿用现有插件：深度 1、前台运行、轮数使用全局值，不把缺省误写成新的显式覆盖。

复制读取原预设内容，要求用户填写新的内部名称，不改动源文件。

保存使用与运行时一致的字段校验，并显示字段旁的错误。重名不覆盖；保存失败保留草稿和错误原因。返回列表、取消或刷新会丢弃未保存更改时先确认。切换宿主其他页保留当前客户端的草稿，返回管理页继续；不承诺跨重启或卸载恢复。

### 原文修复页

展示错误原因及完整文件原文，允许修复后保存。使用同一解析规则验证；仍有错误时保留草稿与诊断，不将错误状态报告为保存并生效。修复后的内部名称须与目标文件名一致，不通过原文修复绕过名称固定规则；缺失或不一致的名称可纠正为该文件的目标标识。

### 删除与显示名变更

删除确认显示具体预设名称/文件名及当前目录共享影响。确认后删除目标文件并刷新名册。删除失败保留列表条目并显示原因，不删除其他文件，不停止已启动任务。

已有预设增加、清除或修改显示名时，保存前明确说明：当前插件用显示标签查找历史任务，变更可能使旧任务无法按名称续跑或追问；用户确认后才提交。相同显示名不重复提示。不自动修改历史会话，也不借本功能改变续跑协议。

## 数据与保存边界

- 复用已有目录解析和 `parseAgentMarkdown` 规则，避免产生 UI 接受但运行时拒绝的预设。
- 读操作取得原始文件内容和版本标记；不能只保留解析后的字段。现有解析器会忽略未知字段并规范化正文空白，因此不能用其输出整体重写原文件。
- 表单保存仅更新用户编辑的已知字段和正文；保留未编辑的原文、未知字段、注释及扩展内容。遇到不能安全保留的文档结构，明确引导原文编辑，不静默丢弃内容。
- 保存和删除都校验读取时的版本。文件被外部修改或删除时拒绝盲目覆盖，保留草稿并提示重新加载；创建采用不覆盖语义。
- 写入须避免半写文件；出现权限、磁盘或目录错误时返回真实错误，不清空原文件。
- 宿主只操作自身配置解析出的目录。请求传受校验的文件标识，不接受任意绝对路径；防止路径穿越、平台保留名和符号链接将读写导向目录之外。
- 浏览器通过宿主支持的通信通道调用插件宿主侧的读写，不使用终端命令代写文件。写操作须沿用宿主的身份验证/同源保护，不额外开服务端口，不以宽松 CORS 暴露任意文件操作。

## 名册刷新与运行中任务

界面列表读取实时文件；模型名册还需要同步更新 dispatch 工具描述与参数中的名称列表。保存、删除及显式刷新后更新这一注册信息，不要求用户重启客户端。

刷新应仅替换相关注册信息，保持工具名、参数与权限语义，保留前后台派发、续跑、追问和英文委派指导。不得通过重启整个插件来中断正在执行的调用或任务。正在进行的模型请求可能已经持有旧快照；更新从后续模型请求生效。

外部文件变化不增加常驻目录监听；用户打开页面或点击刷新时读取并同步。外部编辑后的实际调用仍沿用现有的按次读文件行为。

## 实现前需要核实的技术事实

以下是需要工程核实的事项，不是尚未回答的产品问题：

1. 需要分别核实两条宿主线的 `settings.section` 入口、主工作区页面注册与导航、离开页面拦截，以及表单 primitives 的公共 API；优先复用共同部分和已有样式。
2. 已生成的 `ctx.remote` 命名空间不能随意扩展。客户端采用公开 `ctx.connection.rpc.call('/api', 'subagent-presets/<endpoint>', payload)`；宿主通过同一 Connection 服务的公开 `fetch.register` 注册对应 exact 路径，复用 `/api` 的身份及 Host/Origin 检查。模型下拉复用现有 `remote.session.modelCatalog()`。
3. 运行阶段发现：两版公开 `connection.rpc.handle` 在 Cordis service getter 捕获提供者 shadow context，注册时读取 `webServer` 报 `cannot get property "webServer" without inject`，调用方 inject 不解决。采用上面的公开 Fetch 适配器承载同一 RPC envelope 与相关 `rpcId`，不修改宿主对象、不新增裸写路由、不读取令牌或另开端口。两版真实 HTTP 已验证无身份 401、不可信 Origin 403、拒绝后文件不变、CRUD 与卸载。这里只修正接口实施方法，产品及安全约束不变。
4. 工具名册通过同作用域的公开注册和精确 disposer 更新；不重新挂载整个插件。需要真实 SDK 验证更新期间运行中调用不被取消、作用域及叶子限制不变。
5. 两版公开 `ILayout` 没有全局离页 guard/veto，`beginNavigation` 仅取消异步导航；普通主工作区页面无 `settings.open/openSection`。Q12已确认：自身放弃输入的按钮先确认，宿主切页通过客户端生命周期状态保留草稿，使用宿主设置按钮返回设置，不增加程序化返回指定设置页。

Comet Shape 应先完成这些接口及鉴权接入的只读核实并固化方案；若公开 API 无法满足本设计，明确记录差异再决定，不绕过保护或静默降级。

已核实的关键来源：[Electron 路由分派](<D:/Caiqy/Projects/Github/deepseek-harness/apps/desktop/src/main.ts:664>)、[路径转发与同源检查](<D:/Caiqy/Projects/Github/deepseek-harness/apps/desktop/src/web-document.ts:80>)、[现有受保护的 API 通道](<D:/Caiqy/Projects/Github/deepseek-harness/packages/client/connection/src/index.ts:125>)。`ctx.webServer` 是入站路由服务；`ctx.web` 是出站联网服务，两者不可混用。

## 验收目标

- UI-1：两条宿主均出现 **Subagent 预设** 设置入口；点击后打开主工作区完整管理页，自动展示实际目录内现有预设，错误文件可见且有原因。
- UI-2：管理页中的新增、复制、编辑、修复均进入独立页面，能返回列表，通过宿主按钮打开设置；高级字段折叠，遵循现有设置样式和主题，键盘可操作且字段有标签。自身会放弃输入的动作先确认，切换宿主其他页保留当前客户端草稿。
- CRUD-1：完整覆盖各字段、继承值及提示词的创建、读取、编辑和复制；重名拒绝覆盖，内部名称固定，文件名与可调用标识一致。
- CRUD-2：删除前确认共享影响；只删除目标文件；读写失败不报告成功、不损坏原文。
- DATA-1：额外字段、注释及未编辑正文不会因表单保存丢失；外部修改导致的保存/删除冲突能被检测，草稿保留。
- LIVE-1：新增、修改、删除和手动刷新后，后续模型请求看到最新名册且无需重启；既有运行任务不被中断。
- RESUME-1：显示名变更有明确影响提示及确认；原有续跑/追问机制、英文指导和叶子限制保持，不实施历史迁移。
- SECURITY-1：写请求经过适用的宿主身份/同源保护；不接受任意路径，不穿越配置目录，不跟随目标符号链接写入目录外。
- COMPAT-1：同一插件包在 `0.2.0-rc.2` 与 `0.2.1-alpha.2` 验证页面、数据操作及名册更新；既有宿主和生命周期回归通过。
- DELIVERY-1：使用 Comet 管理实现与独立验收；实际加载并验证安装包，说明构建、安装和重启的生效边界，不以源码测试代替客户端验收。

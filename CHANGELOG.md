# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [0.25.1] - 2026-11-28

### Fixed
- **`agyModel` no longer rejected by an empty model list on real `agy acp`.** Some agy builds return `configOptions.model.options: []` from `session/new` (T39), which made 0.25.0's local whitelist reject every family with an empty `available:` list. The whitelist is now applied only when the list is non-empty; with an empty/missing list the registry still sends `session/set_config_option` and trusts the RPC outcome. An RPC error fails loud with the jsonrpc code retained and the remote message kept log-only; a returned `currentValue` that disagrees with the request still fails loud. The rejection now points to `agy models` for checking family names instead of showing an empty `available:` list. The option reader also accepts real agy's `{value,name}` entries (previously only bare strings, which silently filtered the 11 families down to an empty list). `test/acp-run.test.mjs` covers the empty-list paths, the object-shape path and the 11-family fixture scenarios.

## [0.25.0] - 2026-11-28

### Added
- **Per-call / configured model selection for the built-in `agy` member.** The new volatile `agyModel` config key (default `''` = agy's own default) sets the default ACP model family; `use_agent` gains an optional `agyModel` argument that overrides it for one call and is refused for any other agent (`agyModel only applies to the built-in agy member`). After `session/new` the registry reads `configOptions.model.options`, rejects a family that is not in the list (showing the available families, bounded), then sends the client→server ACP request `session/set_config_option {sessionId, configId:'model', value}`. An RPC error keeps only its JSON-RPC code in the rejection (the remote message stays log-only), and a returned `currentValue` that disagrees with the request also rejects: no silent fallback to the default model. The settlement header shows the effective value agy reports. Only the model family is selected — thinking tiers (`thought_level`) are deliberately out of scope for this release. README (zh/en) and `test/acp-routing.test.mjs` / `test/acp-run.test.mjs` cover the config key, the override, and all failure shapes.

## [0.24.2] - 2026-11-28

### Changed
- **Prompt-level guardrail: a stopped `agy` run is no longer re-dispatched by the model on its own.** The `use_agent` description now states that a cancellation — the user pressed stop, or a result carrying `ACP_ABORTED` / `subagent run was cancelled` — is NOT a transient error; the model must report it and wait for the user's instruction instead of retrying the same task. This only suppresses model behavior: it does not prevent the user from explicitly asking to re-dispatch. Observed on 0.24.1: after the web panel's stop, the parent model re-dispatched the same `agy` task three times, wasting plan quota. `test/acp-routing.test.mjs` pins the rule in the description.

## [0.24.0] - 2026-11-28

### Changed
- **The built-in `agy` member now dispatches its foreground one-shot runs with `delivery: 'parent'` instead of `'caller'`.** It therefore enters the host's `subagent/catalog` with its display name as the label (no fixed `name`, so the host assigns `agent-N`), which makes `list_agents`, the web subagent panel and the host's interrupt tools able to see it. Accepted cost: on every agy call the host packages the complete output into one settlement user message posted back into the parent session (`manager.ts:1125-1141`), so the parent model may take one extra turn and the output is duplicated in context; pressing Esc may also start an extra round. Foreground one-shot semantics (no background / follow-up / resume, `ACP_BUSY` concurrency cap) are unchanged. README (zh/en) carries the user-facing note.

## [0.23.0] - 2026-11-28

### Known limitation
- **Wizard edits rewrite the registry row's whole `config:` block; comments inside that block are lost** (verified on a real TUI profile: two hand-written comment lines above `jevTimeoutMs` disappeared after a wizard write). Put hand-written comments above the `config:` line instead. The `/registry-config` wizard now asks a separate single-select agy switch ("enable agy" / "disable agy"); skipping the question, or an answer with a blank selection, changes nothing — a blank selection never clears the roster toggle, never disables codemode and never flips the agy switch. The opt-in install question keeps its original two rows and never touches agy.

### Added
- **Experimental, disabled by default — dispatch the built-in `agy` member through an in-plugin ACP client on the Google Gemini AI Pro plan quota.** `agyEnabled` defaults to `false`; with it on, `agy` appears in the `use_agent` roster (not in `ask_agent`). agy = Antigravity CLI, driven by the registry's bundled ACP client straight to `agy acp`: no profile dependency, no DeepSeek quota, and agy usage does not enter dsh's usage accounting. Foreground one-shot dispatch only (`background` / `resume` / `fresh` → `ACP_FOREGROUND_ONLY`); concurrency is 1 per dsh process (the second call fails immediately with `ACP_BUSY`, no queue); each call waits for the agy process to exit (task plus exit grace, up to ~9 s); the first call takes ~20–30 s (cold start ~20 s). agy has no local dsh Session, so it does not appear in the subagent panel and cannot be interrupted from it (press Esc to cancel the current tool call). Requires a locally installed and logged-in `agy` (absent / not logged in → no roster entry or `ACP_AUTH_REQUIRED`). Platform: macOS / Linux (Windows unverified). Five config keys (`agyEnabled` / `agyPermission` / `agyTimeoutMs` / `agyHandshakeTimeoutMs` / `agyMaxConcurrent`) plus the opt-in toggle are documented in README (zh/en) and the bundled skill; `agyPermission` defaults to `reject` (the registry does not answer permission requests on the user's behalf and does not restrict what agy may do — that is decided by the local agy's own settings).

## [0.22.0] - 2026-11-26

### Breaking
- **Support matrix narrowed to the latest DSH RC only: `0.2.2-rc.5` with schemastery `3.19.x`.** Every `@deepseek-ai/dsh-*` peer is now `>=0.2.2-rc.5 <0.2.3-0`; older RC lines (0.2.0 / 0.2.1) and the alpha line are neither supported nor tested, and no cross-version session migration is promised. README (zh/en), the dev peer contract and the host matrix now state the same single-RC matrix.
- **Upgrade migration is required.** Move the dsh host to `0.2.2-rc.5` before installing this release (finish or discard in-flight runs first — sessions from older RC lines are not migrated), drop every nested-dispatch configuration (`deep` / `maxDepth`, descendant joins, lineage cancel) and stop branching on the removed cold-resume descendant error code below. Multi-step work moves to the main agent as parallel top-level dispatch or sequential calls.
- **Nested delegation is removed.** The child tool surface drops every spawn tool (`subagent` / `subagent_fork` / `use_agent` and the like), so a child can only complete its own task and any nested dispatch attempt is refused — including an unverifiable caller — with the stable code `DSH_REGISTRY_NESTED_DELEGATION_UNSUPPORTED`. Multi-step work is orchestrated by the main agent — sequentially or by dispatching several top-level subagents in parallel. The guard covers only this plugin's own start/resume tools; nesting through the host's native `subagent` / `subagent_fork` tools is host-managed and outside the plugin's control (no promise to block it). Non-agent CLI/API callers do not call the registry dispatch tools directly: without a verifiable top-level agent identity they are refused by the same guard; use the main conversation or host-native mechanisms instead.
- **No descendant join, aggregation or lineage cancel.** The registry no longer waits for or summarizes descendants, and cancellation no longer propagates along a run lineage; a foreground `use_agent` returns only that child's own result.
- **The cold-resume descendant error code is removed.** `DSH_REGISTRY_COLD_RESUME_DESCENDANT_UNSUPPORTED` is no longer emitted: code that branched on it must be updated (there is no descendant settlement path left to guard).
- **`deep` and `maxDepth` are deprecated and inert.** The `deep` frontmatter and the host `maxDepth` orchestration key are retained for compatibility and ignored at runtime; do not configure `maxDepth` / `deep` for nested orchestration.

### Added
- **caller-guard** — `src/caller-guard.ts` re-checks the caller at every registry entry point that can start or resume an agent (`use_agent.execute`, `activateWithReservedComposition`, `startLegacyForeground`, `driveResumedRun`, `driveLegacyResume`) as its first statement, before any host call, file read or record write. A registry child, a host-forked child or an unverifiable identity fails closed with one stable code, `DSH_REGISTRY_NESTED_DELEGATION_UNSUPPORTED` (`NestedDelegationError`, carried as `error.code` with an actionable next-step hint). `test/caller-guard.test.mjs` pins the guarded entry-point manifest, the single stable code and the no-side-effects refusal; `test/host-activation.test.mjs` covers the unknown-caller refusal.
- **probe:npm / `npm-install-probe` CI job** — `scripts/probe-npm-install.mjs` (the `probe:npm` script) packs this repo and installs the tarball together with the real `dsh@0.2.2-rc.5` host in a scratch consumer under npm's DEFAULT peer resolution — no `--legacy-peer-deps`, no `--force`, no overrides, no repo `.npmrc`. It asserts no ERESOLVE / unmet / invalid-peer warning, every DSH peer at rc.5, exactly one `schemastery@3.19.0`, and no nested `@deepseek-ai` copy; compat failure (exit 1) and registry/network failure (exit 2) print distinct banners. The new `npm-install-probe` CI job runs the probe on every push/PR.
- **devDep** — `@deepseek-ai/dsh-error@0.2.2-rc.5` joins the dev-only rc.5 pin set (devDependencies only; no new peer or runtime dependency), keeping the dev graph aligned with the published rc.5 closure.

### Deprecated
- **`deep` / `maxDepth`** — still accepted so existing configs keep parsing, but inert: they no longer tighten depth or enable nested orchestration (every child is a leaf). Remove them from new configs and orchestrate in the main agent (see Breaking).

### Removed
- **The 0.2.2+ foreground descendant settlement and cancellation path** — `createRunDescendantJoin`, the descendant snapshots aggregated into a foreground result, the run-rooted lineage cancel and the `DSH_REGISTRY_COLD_RESUME_DESCENDANT_UNSUPPORTED` guard for cold-resumed workers deriving descendants are removed along with their code.

### Fixed
- **peer** — all `@deepseek-ai/dsh-*` peers move from `>=0.2.0-rc.2 || >=0.2.1-rc.1` to `>=0.2.2-rc.5 <0.2.3-0`, and `@deepseek-ai/schemastery` from `~3.18.4` to `~3.19.0`; `test/package-compat.test.mjs` pins both default and `includePrerelease` semantics to admit rc.5 and reject rc.4 / alpha / 0.3.0. Entries stay optional peers (`optional: true`) so a consumer never materializes a second copy shadowing the host's bundled closure.
- **devDep** — all 32 `@deepseek-ai/dsh-*` dev pins and `pnpm-lock.yaml` move from the 0.2.2-rc.2 wave to `0.2.2-rc.5` (`cordis@4.1.0` / `schemastery@3.19.0` unchanged); `semver@7.8.5` is added for the offline peer-contract test. `test/package-compat.test.mjs` and `test/delegation-guidance.test.mjs` join the `npm test` chain.

## [0.20.1] - 2026-11-13

### Fixed
- **The published package no longer carries an install lifecycle hook — `postinstall` became `prepare` — so pnpm 11 updates stop failing with `ERR_PNPM_IGNORED_BUILDS` (fixes #10).** pnpm 11 defaults to `strictDepBuilds`: an install of a dependency declaring an unapproved `preinstall`/`install`/`postinstall` exits non-zero, and the dsh host plugin manager rolls the update back — with 0.20.0's `postinstall` every 0.19.1 → 0.20.0 update failed. npm and pnpm never run `prepare` for registry dependencies, and pnpm's gate set is exactly those three install hooks, so the published manifest is now hook-free while the dev closure linking keeps running from the root `prepare` hook (a root install runs it; `npm run link-closure` stays the manual entry; CI's explicit `node scripts/link-dsh-closure.mjs` step is unaffected).

## [0.20.0] - 2026-11-12

### Fixed
- **The rc.2 resume drive no longer calls `waitForTreeWork` with the resumed child — it joins on the tree root `rootOf` resolves, and rides the legacy event join when no root is resolvable.** The real rc.2 manager guards `waitForTreeWork` with `if (this.rootOf(root) !== root) return false` and its `rootOf` throws `UNAUTHORIZED` ("agent has no active runtime owner") for a subagent-origin session outside manager residency — which is exactly what the cold-resume drive child is (it materializes through the agents service, bypassing the manager; every in-process child session carries `origin: 'subagent'`). Calling `waitForTreeWork(child)` therefore threw on a real rc.2 host (cold resume broken outright) and silently resolved `false` for a resident member (hot resume dropped the descendant join), while the host-level `hasNativeChildWorkJoin` probe had also disabled the `createLegacyDescendantJoin` fallback that folds descendant `subagent/end` events into `snapshotEvents(boundary)`. `src/host-compat.ts` now exposes `nativeChildWorkJoinRoot` (pre-rc.2: the parent itself — `waitForChildren` filters by lineage with no root guard; rc.2: the exact live tree root through the runtime's own `rootOf`, `undefined` when that throws) and `waitForChildWork` joins `waitForTreeWork(root)` on the resolved root; `drainRunDescendants` skips the rc.2 manager drain when the agent is not its own tree root (a member owns no tree; the manager's `rootOf` throws for a non-resident agent). The audit's prescribed fix ("prefer `waitForTreeWork(root)` (rc.2)") is now implemented in that exact form. The rc.2-surface test doubles are reshaped after the real runtime (`rootOf` throw / member / self-root instead of a `return false` stub) and pin all three shapes.

## [0.19.1] - 2026-11-06

### Fixed
- **Web and desktop profiles no longer deadlock on `bundle-in-use`, and the web-app's default preset stays `standard` (fixes #9).** The bundle patch declared two agent-preset service rows statically (`agent-preset-registry` with `default: native`, `subagent-model-selection-settings`) whose ids and names are identical to rows `@deepseek-ai/dsh-web-app` inserts. A same-id insert from a later patch layer does not crash the loader — it silently replaces the earlier row wholesale (last writer wins), so on any profile selecting the web-app the merged registry row carried this bundle's `default: native` (flipping the web session default preset to a tool-less `native` row) and `dsh plugin remove` matched the web-app's live rows against this patch file's declared rows forever (`bundle-in-use`). The two service rows are gone from the static patch; the plugin now mounts them at runtime on the include tree (`src/preset-mount.ts`), only where no same-id entry exists — race-free because the loader assigns every composed entry its store slot before any plugin `apply` runs — and tears down exactly the rows it still owns when the plugin fiber disposes (ownership by options identity, so a row a later layer replaced is left to that layer). The teardown also wins the race against the include's own stop(), which runs concurrently with plugin teardown (cordis `Promise.all`s a fiber's disposables) and both flushes the journal and unlinks every remaining entry: a row the host already unlinked is still cancelled in the journal (a remove record through `tree.commit`), and the teardown awaits the journal flush so the removals survive the process-shutdown force exit — a clean stop leaves no runtime rows behind in the profile root config. tui/headless profiles compose exactly the layer they always had; web/desktop profiles keep the web-app's rows untouched.
- **The `preset-native` / `preset-codemode` rows carry a `disabled` guard** keyed on `profileContext.startedBundles` containing `@deepseek-ai/dsh-web-app` (the same `!!js` seam the web-app's own desktop-only rows use): the static rows would otherwise add `Native` / `Codemode` entries to the web preset picker. On every other profile the expression evaluates false and the rows mount as before.
- **The tool-subagent delegation row uses the schema-valid `modelSelection: true` key** — the stray `modelSelectionSettings: true` was not a key of the config schema and sat inert.
- **The patch header no longer claims the loader rejects duplicated ids** — it silently lets the later layer win, which is precisely how the #9 collision stayed invisible. README (zh/en), the bundled skill (zh/en/ru) and `test/patch-ids.test.mjs` now describe the same behavior.

### Added
- **Runtime-mount regression coverage** — `test/preset-mount.test.mjs` exercises mount, dispose, idempotence, skip-when-the-web-app-rows-already-own-the-ids, partial fills, claimed-row teardown, the bare-context no-op, create-failure containment and the host-already-unlinked shutdown race (journal cancellation plus the awaited flush) against a structural include-tree double; `test/patch-ids.test.mjs` now asserts the retired service rows never return as static rows, evaluates the preset-row guard in both worlds (web disables, tui/headless enables), and pins the runtime rows' verbatim config.

### Fixed
- **The Codemode preset instantiates again on the dsh 0.2.2-rc.1 host wave; codemode sessions survive their first prompt turn (fixes #8).** Two host-compat breaks sat in the preset's own patch rows:
  - The delegation group's `tool-subagent-list-agents` row mounted `@deepseek-ai/dsh-tool-subagent-control/list-agents`, a subpath the 0.2.2 control package removed from its `exports` map — importing it throws `ERR_PACKAGE_PATH_NOT_EXPORTED`, and the loader reports the whole preset `never started` (session creation refused). The row now mounts this package's own bridge subpath (`@aiwayds/dsh-subagent-registry/legacy-subagent-list-agents`): the bridge reads the installed control package's manifest through its `./package.json` export (defined on every supported generation) and imports the legacy sub-entry only where the exports map still defines it — pre-0.2.2 towers (0.2.0-rc.2 / 0.2.1-rc.x, whose main entry registers no discovery) keep the legacy mount, 0.2.2+ hosts mount nothing because the main entry's `apply(ctx)` now calls `registerListAgents` itself. The decision is synchronous manifest inspection: no removed subpath is ever imported on 0.2.2+, no module exception is caught, and a genuinely missing control package fails loud.
